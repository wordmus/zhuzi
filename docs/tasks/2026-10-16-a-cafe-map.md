# A · 咖啡厅作为入口总览（第二次来访展开四层）

依据：`docs/design/structure.md`（四层结构）、`docs/design/layers.md`、策划 v0.2 §12（作品架、年谱、灯油默认折叠，第二三次来访随需要出现）、§13（基础导演）；与 `docs/tasks/2026-10-16-b-desk-overview.md`（B：独立总览页）、`docs/tasks/2026-10-16-c-console-ui.md`（C：仪表 UI）互为对照。A 的立场：**入口仍是那间咖啡厅（是呈现、有画面），但第二次起它展开成整台机器的四站**。

目标：不改第一次来访的快路径（推门→灯亮→导师→票根），从**第二次来访**起（`ctx.visit.n >= 2`），咖啡厅多出可展开的四站：**① 灯油台（导师在给谁分油、为什么）→ ② 导演廊（工作台/毛坯/年谱）→ ③ 作品架（呈现与状态）→ ④ 门（进入一件作品）**；另在反引号面板里给一个「看整台机器」的折叠入口（第一次也能看，但不默认摆出来）。

## 一、四站在 café 里长什么样（都是物件，不是文字标签）

| 站 | 物件 | 可见的真实数据 | 可做 |
| --- | --- | --- | --- |
| ① 灯油台 | 灯树上多出几只小灯与一只陶壶；灯焰高低＝分给各世界/作品的份额 | `commission.budget.lamp`、来访史（哪盏灯因为你而挪） | 倒油（+/− 到另一只灯，写 store，**下一次 commission 的 why/budget 真的变**） |
| ② 导演廊 | 矮案后多两张工作台：基础导演与叔衡；台上是未盖印的**毛坯**，墙上钉草稿与年谱（第一天 vs 今天） | 索引的 director 字段、`seed-memory/rules.json`、`bench/history.csv` | 走近看（trace）、撤掉一版（写 store，折叠确认） |
| ③ 作品架 | 启用现有折叠的 `shelf` 元素：每件作品一叠帛／一张卡，盖印的旁边有事实印 | `runs/index.json`（若存在；缺失时优雅显示「架子还空着」） | 拿起一件、展开「为什么值得你看」 |
| ④ 门 | 就是现有的门（地标不动） | 选中作品的 `index.html` 相对路径 | 推门＝新标签页进入；无 URL 时一句「这件还没开门」 |

**第一次来访**：一切照旧（不可见这些站）；**第二次起**：进场时四站已在那里，但只有 1–2 处**因为你上次而变**的地方会动（灯挪了、毛坯换了、年谱多一页）——变化由视线指出，不靠文字说明。

## 二、要新建/改的

- `frameworks/vignette/**`：新增「展开态」的绘制与交互（仍是漆画场景；一屏一个焦点、每屏 ≤1 句 ≤30 字、前 3 秒 ≤1 个可做之事、100ms 内反馈）。
- `director/pipeline/director.ts`：café 幕按 `visit.n` 展开（第一次不展开、第二次起展开）；参数从 ctx 或 store 传入；`validate.ts`/`app/main.ts` 如需只加。
- `engine/types.ts`：如需只加字段（例如 café 展开态的开关与站数据）。
- `intents/first-visit.json`（保持行为）或新增 `intents/cafe-map.json`（直接看展开态的口子，seed 可控）；二者择一，优先不动 first-visit 的既有验收。
- `assets/library/cafe/**`：若需要新画具（小灯、壶、工作台、草稿纸）就放这里并写 recipe。
- `docs/design/cafe-map.md`：四站元素/动作表、与 B/C 的对照（哪种更像入口）、复验命令、边界。

**并行纪律（重要）**：B 工与 C 工也在改 `director.ts` / `validate.ts` / `app/main.ts`。你每次改这三个文件：先重读、只追加自己的一条、改完**检查 `desk`、`console`、`cafe`（以及既有全部）条目都在**；若发现别人的条目被覆盖，补回并在报告里写明。不要碰 `frameworks/desk/**`、`frameworks/console/**`、`desk-plan.ts`、`console-plan.ts`、`intents/desk.json`、`intents/console.json`、`runs/index.json`、`works-index.ts`（那些是别的工的）。
**bench 并发**：机器上可能同时有别的 bench 在跑。若遇到 `feedback p90 none` 或 fps 明显异常，先只重跑一次并注明可能是争抢；不要改门槛。

## 三、验收（都要打印）

```sh
pnpm typecheck
pnpm bench runs/first-visit/13/L1            # 第一次来访的快路径不变，仍 9/9
# 展开态：预置一份 visit.last（visit.n=2）后 present 一个 café-map 的 run
pnpm present --intent intents/cafe-map.json --tier L1 --seed 3 && pnpm bench runs/cafe-map/3/L1
```
- `runs/cafe-map/3/L1` **PASS hard 9/9**（含 layers）；截图能看出四站（灯油/工作台/架子/门）。
- **展开条件自证**：无头或脚本断言——`visit.n = 1` 时不出现四站、`visit.n >= 2` 时出现（同一 seed 两次对比，打印差异）。
- **灯油倒过**：倒油前后同一 intent 的 `commission().why` 与 `budget.lamp` 不同（无头断言，exit 0）。
- 作品架数据：`runs/index.json` 存在时列出真实作品（数量一致）；不存在时显示「架子还空着」，不许编造。
- first-visit/13 与既有其它作品不回归。

## 四、边界

- 不做独立页面、不做 DOM 仪表（那是 B/C 的地盘）；A 的一切都在那间咖啡厅的画面里。
- 不碰 bench 判定与门槛、critic、既有 runs 产物、git；不接模型。
- 末尾在 `docs/design/cafe-map.md` 写三句对照结论：A（场景展开）vs B（独立场景页）vs C（UI 仪表）——哪种最适合当入口、为什么。
