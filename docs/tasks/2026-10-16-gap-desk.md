# 差距①②④ · 导师排期 + 玩法集分组 + 导演年谱（都在 ENTRY 里长出可见面）

依据 `docs/notes/1.md` 的三处差距：导师的行动是**分配资源、理解用户**（现在只有"理解"，"分配"没有可见面）；交付的是**玩法集而不是玩法**（现在一件件散着，没有按"形"的总览）；导演的规则从哪来（`rules.json` 有 30 条规则各带 `source`，`cases.md` 有案例，但没有"年谱"）。

现状：ENTRY（`frameworks/desk/**`）已是四层逐层展开的漆画入口（L0 案上→L1 导师→L2 导演→L3 呈现，右侧黑漆抽屉只装导师明细，`verify-entry.mjs` 全过，bench 9/9）。**结构不许变**，这三件都在它里面长出可见面。

## 一、导师排期（分配资源的可见面，**不许用灯油/份额/比例**）

- 新 `engine/mind/schedule.ts`：`buildSchedule({ visits, previous, hypotheses, works, experience })` → `{ version, entries: [{ intentId, title, form, order, when: 'next'|'later'|'dropped', why: string(≤18), evidence: {kind, ref} }] }`。
  - 排期必须**从真实证据推**：上次停留（`visit.last.dwell`）、你纠正过的假设（`hypotheses.ts`）、`runs/index.json` 里已有哪些形、年谱里哪条规则被违反过。证据进 `evidence`，`why` 是人话一句。
  - 你说过"不要灯油"：**内部字段名也不许叫 lamp/oil**（这轮新写的代码里）；已有的 store 键 `mentor.lamps`/`mentor.lamp.poured` 只允许"读、兼容、然后不用"，不许新增，不许在画面上出现。
- `engine/layers/mentor.ts` 的 `commission()`：`why` 与预算改由 **排期** 决定（排期第一条 = 这次要做的那件；`why` 写成一句把你和排期连起来的话，≤30 字）；用户改过排期（store 键 `mentor.schedule`）时，下一次 `commission().why` 必须**真的不同**。
- 可见面：**L1 导师层**加一件**木牍**（案上），上面是它下一步要做的**一件**（用篆意字写 title，≤6 字）＋一句 `why`（≤18 字）；抽屉里多一段「它下一步的排期」：列出 2–4 条（`next`/`later`/`dropped`），每条可**上移/压后/撤下**（2 字），改动写回 `mentor.schedule` 并持久（重载保留）。空间不够时抽屉里只留 3 条，其余用"还有 N 件"折叠——**抽屉不算主屏 30 字限额**（`verify-entry.mjs` 的判定口径）。

## 二、玩法集总览（L3 按"形"分组）

- L3 现在是"木架＋帛条"逐件聚焦。改成**按形分组**：从 `runs/index.json` 的 `form` 字段归组（真实值以索引为准，例如 vignette / reveal / walk2d / film / gallery / east3d / chronicle / 小游戏等），每组一个**可翻的木牌**（2–4 字，篆意字）＋该组的帛条。
- **一次只在一组里**：进门停在第一组，翻牌切组（翻牌＝动作物件，不是按钮）；组内仍是一次聚焦一件、抽出帛条＝进入（新标签页）。
- 不许出现数字、计数、进度条；组名的字算进主屏 30 字限额，所以**只显示当前组名**（不许 6 个组名同屏）。
- 空组（还没有那种形）显示一块**空木牌**＋一句（≤12 字），不编造作品。

## 三、导演年谱（挂墙，可对照）

- 新 `director/pipeline/experience.ts`：从 `director/seed-memory/rules.json`（每条有 `id/text/param/source`）＋`cases.md`（案例引用规则 id）＋已有 run 证据，生成 `director/seed-memory/experience.json`：
  `{ version, entries: [{ id, rule, why(≤18), source, caseRefs: [案例号], param, firstSeenAt, evidence: {kind, ref} }] }`。
  - 每条都要能回答：这条从哪来（source）、因为哪次失败/成功写下的（caseRefs / evidence）、它现在在管什么（param）。
  - 参考规则 `chronicle`："每位导演和导师台本身都有年谱；第一天的样子挂在墙上，和今天对照"。
- 可见面：**L2 导演层**那块漆屏风上挂**木牍年谱**——一次聚焦 2–3 条（其余退暗），每条木牍＝规则名（≤6 字篆意字）＋一句 `why`（≤18 字）；翻到另一条用**视线/灯焰**（导师或吊灯移过去），不用按钮。
- 年谱缺文件/为空时，屏风上留**空白木牍**＋一句「还没记下什么」（≤8 字），不许编。

## 四、硬规则（全部适用）

- 每屏 ≤1 句 ≤30 字（抽屉不算）；一次一个焦点；焦点靠光/视线；动作是物件；不许文字按钮；不许数字面板/百分比/进度条/计数；不许同屏堆叠多组多站。
- 色板只用 `components/paint` 的 PAL/TONE；字用 `ctx.lines`（Noto Serif SC 栈）+ 程序化篆意字形。
- 不许改动 ENTRY 已有行为：四层逐层展开、可退回、抽屉默认收起、纠正假设改变真实 `commission().why`（`verify-entry.mjs` 全过）。
- 性能与门槛不动：`bench/` 与 critic 的门槛一个字不许动。
