# P4 · 单页瘦身（32MB → ≤12MB）＋ 稳定入口

现状：每份作品是**单文件 HTML**（`viteSingleFile` + `assetsInlineLimit: 1e8`，设计目标是"双击即开、可当 artifact 发"）。一份 32MB，其中 **PNG 25.3MB（13 段 base64）＋ GLB 5.2MB（6 段）＋ 代码 1.3MB**。仓库已 1.7GB，再长下去推不动、打开也慢。

要求：**在保持单文件、双击即开、canvas 不被污染**的前提下把体积压下来（**不要**改成外链图片：file:// 下的外链会污染 canvas，且破坏"双击即开"）。

## 一、瘦身（主要收益：PNG → WebP）

1. 先量清 `assets/library/**` 里 14 张 PNG（22MB）与 6 个 GLB（3.9MB）各自的用途与体积，报告一张表（哪个形在用、原始大小、转换后大小）。
2. **构建期转换**：写一个 Vite 插件（或 `director/pipeline/**` 里的预构建步骤），把被内联的 `.png` 转成 **WebP**（带 alpha；有照片感的用有损 q≈80，硬边的用 near-lossless），仍然以 data URI 内联。
   - 可用的转换器按机器实际情况挑：`which cwebp ffmpeg sips`；用哪个写进报告（**不要** `pnpm add` 新依赖，不许安装）。
   - 转换结果按内容哈希缓存到 `.cache/`（或 `dist/` 同级临时目录），别每次重转；**缓存目录不入库**。
3. **GLB**：只有在**不引入运行时解码器**（Draco/meshopt 需要额外 WASM 内联）的前提下才压；压不动就**明确写进报告的未做到**，附测量。若压，必须证明 3D 场景仍能加载（`frameworks/east3d/idle.test.ts` 通过 + 新 run bench 9/9）。
4. **不许改视觉**：同 intent 同 seed 的新旧构建**同机位截图对比**（至少：案上/导师/导演/呈现四层、以及 film、gallery、east3d 各一帧），像素差要在报告里给出（可接受极小差异，说明来源：WebP 是有损压缩）。
5. **不许改变行为**：`pnpm bench` 9/9；`verify-entry.mjs`、`verify-schedule.mjs`、`verify-activity.mjs` 全部不退化。

## 二、稳定入口（一条链接永远有效）

现在每次出新 entry 都要告诉人"开哪一个 seed"，不方便。要求：

- `pnpm present --intent intents/desk.json …` 成功后**自动刷新** `runs/entry/index.html`——一个 **1KB 级跳转页**（`<meta http-equiv="refresh" content="0;url=../desk/<seed>/<tier>/index.html">` + 一行可见的"正在进入…"与小字链接，万一没跳成功能点），以及 `runs/entry/entry.json`：`{ intent, seed, tier, builtAt, sizeBytes }`。
- 跳转页与 entry.json 由**脚本**生成（`scripts/` 下，Node），present 之后调用；**不要**在 desk 框架里写逻辑。
- 校验脚本 `scripts/verify-entry-path.mjs`：解析跳转页里的 url，断言目标文件存在、是 desk 的最新 seed、entry.json 与之一致。

## 三、验收（都要打印）

```sh
pnpm typecheck
pnpm present --intent intents/desk.json --tier L1 --seed 15 && pnpm bench runs/desk/15/L1          # PASS 9/9
pnpm present --intent intents/three-look-at-sky.json --tier L2 --seed 3 && pnpm bench runs/three-look-at-sky/3/L2   # PASS 9/9
pnpm present --intent intents/shelf-gallery.json --tier L2 --seed 3 && pnpm bench runs/shelf-gallery/3/L2          # PASS 9/9
pnpm present --intent intents/east-suburb-3d.json --tier L3 --seed 5 && pnpm bench runs/east-suburb-3d/5/L3        # PASS 9/9（3D 仍加载）
node frameworks/desk/verify-entry.mjs && node frameworks/desk/verify-activity.mjs   # 不退化
node scripts/verify-slim.mjs      # 新：① 每份新构建 ≤ 12MB（film/gallery/east3d/desk 四形）② PNG→WebP 生效（旧构建里 image/png 段占大头，新构建里 image/webp 为主）③ 页面仍是单文件（除 entry 跳转页外没有外链本地资源）④ runs/entry/index.html 指向最新 desk ⑤ 旧 run 逐字节不变
```
- 报告 before/after 体积表（逐形），并给出**四形新构建的体积**（目标 desk ≤ 12MB，film/gallery 视素材量给实际值并解释）。
- 旧作逐文件 SHA 比对：studio/5、fifty-years/9、desk/13 必须逐字节不变（只有 bench.json/curve.csv 允许被测量重写）。

## 四、边界（严格）

拥有：`vite.config.ts`、`director/pipeline/present.ts`、`scripts/**`、新插件文件（建议 `director/pipeline/slim-plugin.ts`）、`assets/library/**`（只允许新增 WebP/缓存产物，**不改**既有 PNG/GLB/recipe 的字节）、`runs/entry/**`、`docs/design/slimming.md`（新）、`docs/design/roadmap-next.md`（把 P4 标成完成并写实际数字）。
不要碰：`bench/**`、`critic/**`、`frameworks/**`（除为验证所必需的只读使用）、`engine/**`、既有 runs 产物（除你新产的 seed）、git。

收尾 worker_done：三句摘要 + 命令与汇总行 + before/after 体积表 + 截图对比路径 + 未做到的部分（尤其 GLB 是否压了、为什么）。
