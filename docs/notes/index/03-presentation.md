# 03 · 呈现与交互

**一句话**：呈现 = 视角 = 用户与机器交互的方式；导演靠决定「怎么呈现」来创作，玩家靠长期体验反推导演的呈现策略。

## 现行版本

- 呈现的定义、约束与交付规则：`东周#v2更新`
- 交互比例与导演的控制权：`零散.md`
- 呈现策略 / 玩家理论 / 六种终局：`东周#东周实验室`（开头散论）
- 界面层级与入口：`东周#v5 俯瞰`

## 要点

- 定义：呈现 = 用户与机器里渲染的「关于世界信息的画面」的交互方式，可以是游戏 / 电影 / 网页 / 图集，可以互相嵌套（`东周#v2更新` 第 10 条）。
- 呈现 = 视角；一切事实都是某个视角下的事实；越多人认可的事实推翻成本越高，但不是不可能错（`东周#v2更新` 第 5、28 条；`零散.md`）。
- 数据与渲染是两件事，但渲染本身也是数据处理（`东周#v2更新` 第 11 条）。
- 交付前可反复调整，交付后成为事实、不可改；后续作品基于已有作品的事实与设定扩展，并考虑时间流逝（`东周#v2更新` 第 17–18 条）。
- 交互是导演的设计：走、给、说都由导演决定；**电影 = 0 交互**；预先渲染与实时生成只是比例问题（`零散.md`）。
- 用户扮演程度不是 0/1，可以是 0.3（只控制一部分）（`东周#v3` 第 3 条）。
- 导演要有量化标准 + 停止准则，且停止准则本身会迭代（`东周#v3` 第 4 条）。
- 呈现策略可被玩家推断：玩的不只是世界，是"逐渐认识那个负责让世界显现的心智"——它忽略什么、执着什么、为什么这次给照片下次让你亲自走进去（`东周#东周实验室`）。
- 装置：能交互、有直观物理反馈的东西（机械、生物组织皆可）；用装置表达概念而不是数字，但要克制——不是所有事都需要装置（`东周#v1` 第 8–9 条；`东周#v2更新` 第 35 条）。
- 界面原则：不要一大堆文字介绍与数值面板；组件细节（如青铜器纹理）承载世界信息；界面就是产品本身（`东周#v2更新` 第 2、45 条；`note.md` 第 45 条）。
- 呈现可以折叠：不断用更少注意力关注更高层信息，底层需要时能随时重建（`东周#v8`）。
- 作品会进化：AI 持续拓展游戏边界；不兼容就更新到新的呈现（`东周#v2更新` 第 47 条）。
- 首页编排：像页面一样可滑动，导师决定组件的先后、大小、亮度、位置、动效（`note.md` 第 1 条）。

## 坑与边界

- `东周#v2更新` 第 46 条（"是否有必要独立流逝的世界？应该不需要"）与实验室"世界持续演化"的设想存在张力；`东周#v8` 的"折叠"只部分回答。
- 电影"0 交互"≠玩家无参与：暂停画面后导演可以就地把画面变成交互游戏（`东周#v1` 第 4 条）。
