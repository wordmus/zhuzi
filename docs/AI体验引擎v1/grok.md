# 东周实验室之二：娱乐引擎（体验引擎）技术设计文档

**版本**：v0.1  
**目标受众**：Coding Agent（如 Cursor、Claude Code、OpenCode 等）  
**设计者**：青竹  
**目的**：将理念转化为可执行的模块化系统原型。构建一台“只为一个人存在的机器”，其中一切呈现由多层心智（导师-导演-演员）设计并随用户体验共同进化。

---

## 1. 核心原则与约束

1. **LLM 是意义翻译器**  
   - LLM 专注高层信息：主题、意图、概念压缩、用户理解、设计决策。  
   - 低层模拟（感官模块、记忆痕迹激活、行动单元）优先用符号结构 / 规则 / 结构化状态处理，避免将一切塞给 LLM。  
   - 导师层最接近人类时间流逝；其他层服务于呈现，时间可独立（叙事时间、加速时间）。

2. **多层角色 = 快慢分层设计**  
   - **导师（Mentor）**：慢层。理解用户、分配资源、维护自身连续心智（秘密花园）、历史档案。  
   - **导演（Director）**：中层。接收主题，设计世界设定与呈现，可嵌套（双世界）。  
   - **演员 / 世界（Actor / World）**：快层。活在设定中，运行心智模型，产生行动。

3. **环境与心智相互作用**  
   - 呈现 = 导演对世界的理解 + 以某个交互体验为目标的建模。  
   - 用户交互验证预期（游戏端）或接受导演控制（电影端），处于光谱上。  
   - 生成资产（文生图/视频/音频）可反馈并改造设定，由相关心智决定“去留”。

4. **心智模型**  
   - 行动单元层级搭建 → 高层决策。  
   - 信息压缩表征高层概念（例：墨家“兼爱”）。  
   - 记忆 = 连续痕迹；意识 = 时间窗口内痕迹的记录（记录本身也是痕迹）。  
   - 符号化优先于硬编码函数。  
   - 共同进化：导演设计能力边界，通过人类知识注入 + 用户交互数据持续改进。

5. **工程约束**  
   - 呈现分解为可组合基本单元（交互控制器、剧情器、技能模块、镜头控制器等）。  
   - 单用户专属，状态持久化，时间锚点增强私人感。  
   - 初始聚焦历史类 RPG（心智数值驱动，而非传统概念数值），可扩展到其他呈现。

## 2. 系统总体架构

```
用户交互 (Input/Output)
        ↓↑
呈现引擎 (Presentation Engine)
  - 多模态渲染、单元组合、交互映射
        ↓↑
世界运行器 (World Runner) + 演员心智 (Actor Minds)
        ↓↑
导演层 (Director Agents)
  - 世界设定生成、呈现设计、迭代
        ↓↑
导师层 (Mentor)
  - 用户模型、资源分配、秘密花园、历史档案
        ↓↑
共享基础设施
  - 状态存储 (Hierarchical State Store)
  - LLM 接口 (High-level only)
  - 知识库 / 历史人物资料
  - 多模态生成服务
  - 时间管理器 (Multi-rate clocks)
```

**数据流关键原则**：
- 高层决策（主题、设计意图）→ 向下参数化。
- 低层事件 / 用户反馈 → 向上压缩为信号，触发高层更新。
- 所有层保留自己的历史与经验痕迹。

## 3. 模块详细设计

### 3.1 导师模块 (Mentor)

**职责**：
- 维护用户模型（偏好、历史交互、预期模式）。
- 分配主题 / 资源给导演（可 spawn 新导演实例）。
- 维护自身连续空间：**秘密花园**（空间锚点，随用户时间缓慢演化，避免突变）。
- 记录自身“经历”（文件操作、时间流逝、决策、对用户资料的理解）。
- 回答元问题（如“你现在感觉如何？”）时基于自身档案，而非通用知识。

**状态 Schema 示例**：
```json
{
  "id": "mentor",
  "user_model": { "preferences": {}, "interaction_history_summary": "", "current_expectations": [] },
  "garden_state": {
    "description": "当前花园视觉/空间描述",
    "evolution_stage": 0.3,
    "last_user_sync_time": "ISO8601",
    "elements": ["bamboo", "pond", "path"]
  },
  "self_history": [
    { "timestamp": "", "event": "assigned theme X to director Y", "reflection": "" }
  ],
  "active_directors": ["dir_001"]
}
```

**时间**：与用户会话 / 现实时间对齐。花园改造节奏与用户时间流逝同步。

**LLM 使用**：仅高层。提示聚焦“根据用户资料与自身档案，决定下一个主题 / 对花园的缓慢改造建议 / 对用户意图的理解”。

### 3.2 导演模块 (Director)

**职责**：
- 接收导师主题。
- 设计世界设定（参数 + 提示词 / 符号约束）。
- 生成 / 迭代呈现（可选择光谱位置：更电影 or 更游戏）。
- 支持嵌套：导演所在世界 + 其设计的子世界（双世界）。首次由青竹设计结构，后续由导师填参。
- 设计过程本身可被呈现（传记式披露）。
- 评估自身能力边界，请求新能力或 spawn 辅助角色。

**工作流**：
1. 接收主题 + 约束。
2. 生成世界设定草案（结构化）。
3. 设计呈现单元组合。
4. 运行 / 模拟预期体验。
5. 根据反馈调整。

**状态**：个人经验、公共知识引用、当前项目模型、对子世界的理解。

### 3.3 世界运行器与演员心智 (World + Actor)

**世界**：
- 设定 + 运行规则。
- 支持历史类 RPG 初始场景（基于历史人物资料初始化模型与参数）。
- 时间可独立于用户。

**演员心智**：
- 模块化：感官、驱动力（如“胃”对食物的倾向）、记忆痕迹、高层概念。
- 决策：高层聚合底层信号，过滤噪声。
- 对其他角色的认知 = 基于自身结构 + 情景参数化。

**心智状态 Schema 示例**：
```json
{
  "id": "actor_mozi",
  "base_profile": "历史资料摘要",
  "modules": {
    "drives": [{ "name": "兼爱倾向", "activation": 0.8, "triggers": [] }],
    "memory_traces": [
      { "id": "t1", "content_compressed": "", "activation_level": 0.4, "timestamp_range": [] }
    ],
    "high_level_concepts": {
      "兼爱": { "compression": "symbolic_or_embedding_ref", "relations": [] }
    }
  },
  "consciousness_window": ["trace_ids"],
  "current_action_intent": ""
}
```

**信息压缩**：高层概念用结构化符号或压缩表示。激活机制非简单时间衰减，结合环境反馈与模块连续性。

### 3.4 呈现引擎 (Presentation Engine)

**基本单元**：
- 交互控制器（处理用户输入 → 世界行动）。
- 剧情 / 事件器。
- 技能 / 能力模块（可组合）。
- 镜头 / 感知控制器（电影端）。
- 多模态生成调用器。

**光谱控制**：
- 导演可设定交互深度（全控镜头 vs 用户自由探索规则）。
- 用户预期验证在游戏端发生，反馈压缩后上传。

**多模态**：文生图、视频、音频资产生成后，由相关心智（导演或演员）决定是否保留并改造设定。

## 4. 时间与进化机制

- **多速率时钟**：
  - Mentor Clock：用户同步。
  - Director / World Clock：可加速、暂停、叙事跳跃。
- **共同进化**：
  - 人类知识通过 LLM 高层注入。
  - 用户交互数据 → 压缩信号 → 更新用户模型、导演经验、演员参数。
  - 导演持续新增能力直到达到目标体验。
- **秘密花园演化**：每次用户会话后，基于时间流逝 + 交互摘要，缓慢修改花园状态（LLM 建议 + 规则约束，避免跳变）。

---

## 5. LLM 集成规范

- **调用层级**：主要在 Mentor 和 Director 高层决策。Actor 决策优先符号模型，复杂时才调用。
- **提示原则**：
  - 提供压缩后的高层摘要，而非原始日志。
  - 明确角色：“你是导师，基于自身档案与用户资料...”
  - 要求结构化输出（JSON schema）。
- **示例提示片段**：
  > 根据以下用户模型摘要与你的历史档案，决定是否分配新主题。输出 JSON：{ "decision": "assign|wait", "theme": "...", "reason": "..." }

---

## 6. 存储与持久化

- 推荐：分层 JSON / 图存储（每个心智独立状态 + 关系边）。
- 记忆：向量检索 + 符号索引混合（用于压缩与激活）。
- 历史档案：追加式日志，定期压缩为高层摘要。
- 单用户，本地优先（可结合用户 Mac 环境）。

## 7. 实施路线图（建议 Coding Agent 按阶段执行）

### Phase 1：最小可行原型（MVP）
- 实现 Mentor 基础：用户模型更新、简单秘密花园状态（文本描述）、主题分配。
- 单一 Director：接收主题，生成简单文本呈现（或基础交互场景）。
- 基础持久化与会话循环。
- 目标：用户能感觉到“连续的心智在设计体验”。

### Phase 2：心智模型基础
- 实现 Actor 模块结构、记忆痕迹、简单压缩。
- 历史人物初始化流程（资料 → 参数）。
- 导演可迭代呈现。

### Phase 3：嵌套与多模态
- 双世界结构。
- 呈现单元分解与组合。
- 接入多模态生成，资产反馈机制。
- 秘密花园可视化 / 生成描述演化。

### Phase 4：共同进化与光谱
- 反馈循环完善。
- 电影-游戏光谱参数化。
- 导演能力扩展与 self-assessment。

## 8. 技术建议（供 Agent 参考，可调整）

- **语言**：Python（本地优先）。
- **Agent 编排**：自定义层级循环，或 LangGraph / 类似图状态机。
- **状态**：Pydantic 模型 + JSON 持久化，或轻量图 DB。
- **LLM**：通过统一接口，高层调用。支持结构化输出。
- **多模态**：预留生成服务接口（可灵、即梦、或其他）。
- **UI**：初期文本 / 简单 Web 或本地界面；后期可扩展 Mac App。
- **目录建议**：
  ```
  /mentor
  /director
  /world
  /mind_model
  /presentation
  /storage
  /llm_interface
  /time_manager
  main_loop.py
  ```

## 9. 示例工作流

1. 用户开启会话。
2. Mentor 读取上次状态，根据流逝时间更新秘密花园（缓慢变化），加载用户模型。
3. Mentor 决定主题（例：“战国时期墨家思想的日常体验”），分配给 Director。
4. Director 生成世界设定（历史人物墨子风格演员、环境规则）。
5. 呈现引擎组合单元，生成当前场景（文本 + 可选图像）。
6. 用户交互 → 映射为世界行动 → 演员心智更新 → 反馈压缩上传。
7. 会话结束：Mentor 归档经历，准备下次花园演化。
