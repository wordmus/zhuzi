# 呈现管线 · 给 coding agent 的工作说明

## 0. 一句话

你不是在做游戏和电影，你在做**导演用来做游戏和电影的管线**。
任何一件作品变好了，都必须能被导演在没有你的情况下从零重新做出来；做不出来，这次改进不算数。

衡量你工作的不是「最好的那一件有多好」，而是**管线复现率**：拿一个新意图、新 seed，不经你的手，导演能做到多好。

---

## 1. 放进 CLAUDE.md 的常驻规则（直接复制）

```markdown
# 本仓库的铁律

1. 作品只能由导演管线产出：
   pnpm present --intent <file> --tier <L0-L4> --seed <n>
   不要手写或手改某一件作品的产物。

2. 对产物不满意时，只能改下面六处之一，并在 commit 信息里写明改的是哪一处：
   frameworks/              玩法与形式框架（walk2d、vignette、gallery、animatic、film…）
   components/              界面与装置组件
   assets/library/          可复用资产（每件带来源、许可、生成配方）
   eras/<era>/style-bible.md  时代的色板、材质、光照、构图、声音规则
   director/seed-memory/    导演的种子规则与参考案例
   critic/                  评审规则与参考集

3. 每次改动后，用新的 seed 从零重跑一次管线，证明改进能复现；复现失败就回退。

4. 硬指标（字数、首个可操作时间、反馈延迟、帧率、报错）由 bench 脚本判，不由你判。

5. 审美分只来自 critic（与生成不同的模型，看截图，与参考集做配对比较）。你不给自己的产物打分。

6. golden/holdout/ 只用于评测，不得读取用于生成或调参。

7. 每次 /goal 达成后，把 bench/thresholds.json 里对应门槛上调一档（棘轮），只升不降。
```

## 1.5 开工前由人准备的东西（coding agent 不替你做）

| 放哪 | 是什么 | 最少数量 |
|---|---|---|
| intents/ | 测试意图 JSON：目标体验、视角、形式、时长、停止准则 | 2–3 个（《旱》第一幕、三人看天） |
| critic/golden/ | 你认为「有口味」的参考截图或镜头帧 | 3 件 |
| critic/golden/bad/ | 你不要的样子：像说明书、太满、材质跑时代 | 3 件 |
| critic/golden/holdout/ | 只评不看的参考 | 3–5 件 |
| eras/zhanguo/style-bible.md | 色板、材质、光照、构图、声音（可让 agent 起草，你改定） | 1 份 |
| critic/references/<作品>/ | 参考卡 card.md，加你亲自记录的体验谱 curve.csv（见第 3.6 节） | 先做太阁 1 份 |
| .env | 生成用的模型、critic 用的另一个模型、Tripo 与视频 API 的 key | — |

参考集决定了 critic 学到的口味，所以只能由你来挑。若仓库要开源，critic/golden/ 里来自商业作品的截图不要提交到公开仓库，放在本地或私有子模块里。

```

  seed-memory/       第 2 节设计原理写成的规则 + 3–5 个好/坏案例
  pipeline/          意图 → 呈现方案 → 构建 → 试映 → 修订 → 交付
critic/
  rubric.md          软指标维度
  golden/            好的参考（游戏截图、镜头帧、分镜）
```

## 3. 评审：把「精美」变成能打印出来的数

/goal 的完成判定由一个小模型读对话记录来做。它看不见画面，只认打印在记录里的结果。所以**先建 bench，再做作品**。

### 3.1 硬指标（Playwright 驱动，脚本判）

| 指标 | 初始门槛 | 来自哪条设计原理 |
|---|---|---|
| 进入后首个可操作元素出现 | ≤ 3 秒 | 进入场景前 3 秒只给一个能做的动作 |
| 每个动作的可见反馈 | ≤ 1 秒（目标 100ms） | 每个动作一秒内有反馈 |
| 每屏可见文字 | ≤ 1 句（中文约 30 字） | 读字最贵 |
| 同时在明显运动的区域 | 1 个焦点 + 低对比背景 | 一屏一个焦点（逐帧差分统计运动区域） |
| 帧率 p5（参考机） | ≥ 50 fps | 手上要有回应 |
| 3D 预算 | 三角面、draw call、贴图总量上限 | 用户机器不是工作站 |
| 控制台报错 | 0 | — |
| **删字测试** | 隐藏全部文字后，模拟玩家仍能完成第一幕 | 文档 2.4 的检验 |

### 3.2 软指标（critic 判）

- 输入：每幕 3–5 张截图（电影每镜抽 3 帧）+ 该件的意图 + 时代 style bible。
- 方式：**与参考集配对比较**（「A 和 B 哪个更像一个有口味的导演做的？哪个更符合战国的材质？」），不打绝对分。配对比较比打分稳定得多。
- 维度：焦点是否清楚；材质与时代是否一致；构图；色彩是否统一；动效是否有意图；**风格可辨**（同一导演的三件作品混进别人的作品里，critic 能否挑出来）。
- 输出：bench/report.json，并在 stdout 打印一行汇总：`PASS hard 8/8 · critic winrate 0.42 (n=12) · repro 0.88`。

### 3.3 模拟玩家

和导演试映用的是同一个：逐步报告「我以为会怎样 / 实际怎样 / 想不想继续」。它的报告写进 report.json，作为编排修订的输入。

### 3.4 防刷分

- critic 与生成用不同的模型；critic 不看生成提示词。
- holdout 集只评不看。
- 每周人工排序 5 对作品；人与 critic 的一致率低于 70%，先修 critic，再继续优化作品。
- 分数在涨、人看不出差别时，停下来，记进 notes/。

### 3.5 先验证 bench 本身

bench 能把 golden/ 判为通过、把 golden/bad/ 判为不通过，才算可用。

### 3.6 参考作品：拆成维度来对照，不模仿长相

一部参考作品只负责它最擅长的一两个维度。critic 永远按维度提问（「哪个焦点更清楚」「哪个材质更像先秦」），**从不问「哪个更像某某游戏」**。参考截图不进公开仓库，不用来做图生图或任何生成输入。

**参考卡模板**（critic/references/<作品>/card.md）

```markdown
# 参考卡 · <作品名>

## 负责的维度
<一两个维度，例：生活骨架、身份自由>

## 取
- <可以写成规格的结构，例：身份决定可去的场所与可做的动作>
- <例：设施即动作入口；时间按旬推进>
- <例：三层循环——一旬内的事 / 一季的事 / 身份晋升；事件打断日常>

## 不取
- <明确拒绝的东西，例：数值面板、菜单树、属性条>

## 怎么测
| 指标 | 怎么算 | 参考值 |
|---|---|---|
| <例：每种身份的不同动作数> | 读呈现方案 JSON | ≥ N |
| <例：动作到可见后果的时间> | 模拟玩家日志 | ≤ X 秒 |
| <例：每旬事件打断次数> | 模拟玩家日志 | ≥ 1 |
| 决策密度、屏上数字 | 体验谱 curve.csv | 见下 |

## 截图
shots/ 下 <n> 张，各标注对应哪个维度。
```

**首批参考与维度**（按需增减）

| 维度 | 参考 | 取 |
|---|---|---|
| 生活骨架、身份自由 | 太阁立志传 | 身份×场所×动作；时间节奏；三层循环 |
| 时代材质进入界面 | Pentiment | 界面、字体、画面都是那个时代的材质 |
| 心智可见、部分控制 | Disco Elysium | 技能是内心的声音；只能影响不能全控 |
| 装置式交互 | Gorogoa | 画面本身是机关，几乎无字 |
| 视角与控制一致 | Return of the Obra Dinn | 只能看已发生的一刻，限制即玩法 |
| 极简操作承载重决定 | Reigns | 一个手势背后是一个国家 |
| 先秦材质 | 战国器物照片（漆器、青铜纹样、帛书） | 色板、纹样、质感；进 eras/zhanguo/ref/ |

**体验谱**（critic/references/<作品>/curve.csv）

由你亲自玩参考作品 30 分钟，每分钟记一行。模拟玩家玩我们的作品时，按同一格式输出 runs/<…>/curve.csv，bench 比较两条曲线。

```csv
minute,decisions,new_info,want_continue,numbers_on_screen,words_on_screen,note
1,2,3,4,18,40,选身份；城下町地图一眼看懂
2,4,1,4,22,25,去酒馆打听，得一条传闻
3,3,2,3,22,30,…
```

| 列 | 含义 |
|---|---|
| decisions | 这一分钟做了几个有后果的选择（移动、对话分支、承诺；纯翻页不算） |
| new_info | 得到几条之前不知道的事 |
| want_continue | 1–5，想不想继续 |
| numbers_on_screen | 这一分钟里典型一屏上的数字个数 |
| words_on_screen | 典型一屏上的字数 |
| note | 一句话：发生了什么、为什么想或不想继续 |

bench 从曲线算出四个汇总量：决策密度（每分钟决策数的中位数）、首个有后果的决策出现的分钟、want_continue 的最低点与结尾值、每屏数字的中位数。

**北极星**：决策密度不低于太阁，屏上数字少一个数量级。

## 4. 资源档位 L0–L4

| 档 | 用到 | 适合的形式 |
|---|---|---|
| L0 | 现有组件 + 文字 | 图集式、皮影式、文字冒险 |
| L1 | + 资产库 + 程序化 2D（canvas / SVG / shader） | 2D 小场景游戏、装置 |
| L2 | + 图像生成（带风格参考图与角色设定图） | 插画图集、animatic 短片 |
| L3 | + Tripo → Blender → three.js | 3D 小场景 |
| L4 | + 视频生成 | 电影 |

规则：

- **每个框架必须在 L0 或 L1 就是成立的作品**，不是「低配版」。
- 高档是对同一份呈现方案的**呈现层升级**：事实账本不变，只换画面。这样作品可以先交付、后显影。
- 档位由导师按灯油与用户机器决定，管线必须对任意档都能跑通。

## 5. 游戏管线

```
意图
→ 呈现方案（JSON：幕、每幕焦点、可做的动作、揭示顺序、不给的东西、对玩家的预测）
→ 选框架、填槽
→ 资产解析：库里有就用；没有就按档生成 → 后处理 → 入库（带配方）
→ 构建
→ 试映：截图 + 模拟玩家
→ critic
→ 修编排（最多 N 轮，按停止准则收）
→ 交付，写入事实账本
```

**3D 子管线**（L3）：Tripo 生成 → Blender 无界面脚本：统一比例与朝向、减面到预算、合并材质、按时代色板烘焙、导出 glb 与 LOD → 入库。配方（提示词、seed、参数）随资产保存，便于以后用更好的模型重做。

**看起来精致的最便宜来源是统一**：所有资产（生成的、手做的）都过同一套后处理——时代 LUT、统一描边或质感 shader、统一光照预设、统一的环境音底。先把这层做好，再追单件资产的质量。

## 6. 电影管线

```
意图
→ 节拍（3–7 拍）
→ 镜头表 JSON（每镜：时长、景别、机位运动、焦点、台词、声音、可交互热点）
→ 角色与场景设定图（每部只定一次，之后每镜都以它为参考）
→ 每镜关键帧（图像生成，带设定图参考）
→ 【L2 到此】animatic：关键帧 + 推拉摇移 + 配音 + 配乐
→ 【L4】图生视频，每镜一段短片
→ 拼接（ffmpeg）+ TTS + 配乐 + 音效 + 字幕
→ 试映：抽帧检查角色一致性（脸与服饰的 embedding 相似度）、镜头节奏、每镜字幕字数
→ 交付
```

- 视频与图像模型统一走一层 provider 适配（现用 litellm 或各家 API），配方里记下用的是哪个模型，换模型只换适配层。
- 镜头表里预留热点：电影在任何地方暂停，都能点画面里的东西；导演可以从这一帧派生一个小游戏。
- animatic 本身是一种成立的电影形式，不是预览。L4 出来后作为新版本挂上，旧版留在年谱里。

## 7. 用 /goal 和 /loop

- **/goal**：一个终点，判据能打印出来。下面每条都写清了「验证命令」和「不许碰什么」。
- **/loop**：按间隔重复的事——夜跑基准、轮询长任务。它只在会话开着时运行；要长期跑，改用定时任务或 CI。

### /goal 模板（按顺序做）

**G0 · 管线骨架**（G1 之前必须先有它）
```
/goal pnpm present --intent intents/han-act1.json --tier L0 --seed 1 能从零跑完「意图 → 呈现方案 JSON → 选框架填槽 → 构建 → 截图」，产物落在 runs/han-act1/1/L0/，含 plan.json、可在浏览器打开的 index.html、至少 3 张截图和 trace.jsonl。换 --seed 2 重跑一次也成功。打印两次的产物清单。框架只需一个最简的 vignette，不追求好看。
```

**G1 · 建 bench**
```
/goal bench/run.sh 能对任一 runs/ 目录跑完硬指标与 critic，生成 bench/report.json，并在 stdout 打印一行 PASS/FAIL 汇总。对 critic/golden/ 下 3 件参考全部 PASS，对 critic/golden/bad/ 下 3 件反例全部 FAIL。把这 6 次的汇总行打印出来。
```

**G2 · 第一个框架跑通**
```
/goal 用 pnpm present --intent intents/han-act1.json --tier L1 从零生成《旱》第一幕，连续 3 个不同 seed 都满足：硬指标全 PASS，critic 对 golden 的配对胜率 ≥ 0.40。打印三次的汇总行。不得修改 intents/ 与 critic/。
```

**G3 · 复现率**
```
/goal intents/ 下全部意图各跑 2 个 seed，硬指标通过率 ≥ 90%，critic 中位胜率 ≥ 0.35，打印汇总表。只允许改 frameworks/ components/ assets/library/ eras/ director/seed-memory/。
```

**G4 · 低档不掉价**
```
/goal 同一意图在 L1 与 L3 各跑一次：L1 的 critic 胜率不低于 L3 的 75%，且两版的事实账本 diff 为空。打印两版分数与 diff 结果。
```

**G5 · 电影 animatic**
```
/goal pnpm present --intent intents/three-look-at-sky.json --form film --tier L2 产出一部 60–90 秒的 animatic：镜头表通过 schema 校验，角色一致性最低分 ≥ 阈值，每镜字幕 ≤ 1 句，critic 对 golden/film 的胜率 ≥ 0.35。打印各项。
```

**G6 · 风格可辨**
```
/goal 给导演 A 与导演 B 各一份不同的 seed-memory，各做 3 件作品；critic 在 6 件混排中把作品归到正确导演的准确率 ≥ 80%。打印混淆矩阵。
```

**G7 · 对照太阁的骨架与体验谱**（前提：你已录好 critic/references/taiko/curve.csv，写好 intents/he-one-xun.json「禾在临淄的一旬」）
```
/goal pnpm present --intent intents/he-one-xun.json --tier L1 连续 3 个不同 seed 都满足：taiko 参考卡「怎么测」表中的骨架指标全部达到参考值；模拟玩家的决策密度 ≥ references/taiko/curve.csv 的 90%；首个有后果的决策不晚于参考；每屏可见数字的中位数 ≤ 参考的 1/10；critic 在「焦点」「先秦材质」两维对参考面板的胜率 ≥ 0.40。打印三次的各项与曲线对比表。不得修改 critic/references/ 与 intents/。
```

每达成一条，按 CLAUDE.md 第 7 条上调门槛，再开下一轮。

### /loop 模板

```
/loop 2h 跑 bench/nightly.sh（固定 seed 集），结果追加到 bench/history.csv；任一指标比近 7 次中位数差 10% 以上，在 notes/regressions.md 记下是哪次提交引起的。
```

```
/loop 10m 检查 jobs/ 里 Tripo 与视频生成任务：完成的跑后处理并入库，失败的按配方重试一次，第二次失败写进 notes/jobs.md。
```

## 8. 每周人工 10 分钟

看 5 对作品，排序，写一句为什么。结果放进 critic/human/，既校准 critic，也是导演种子记忆里「好与坏」的新案例。

## 9. 不要做

- 不为宣讲手做一件管线做不出来的作品。真要做，标明「手工」，不进入产品路径。
- 不追全 3D 场景。先把 L1 做到让人想截图。
- 不用停留时长当指标。
- 不让 critic 看到生成提示词，也不把 holdout 当参考。
- 不以「像某部作品」为目标；参考截图不做任何生成输入，不进公开仓库。
